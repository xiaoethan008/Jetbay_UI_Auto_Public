# 报告版本号规则

## 核心规则

回归报告、Allure 管理摘要、问题清单、专项脚本输出中的版本号，必须跟随当前最新测试版本号。

例如当前版本是 `V4.1.1` 时，报告顶部、`quality_results.json`、`官网回归质量报告_<version>`、GitHub Actions 环境变量和专项脚本默认版本都应使用 `V4.1.1`，不能继续沿用 `V4.0.3` 等历史默认值。

## 执行要求

| 场景 | 要求 |
| --- | --- |
| 新版本开测 | 确认当前最新测试版本号，并同步更新 `QA_REPORT_VERSION` 和质量报告默认版本。 |
| GitHub 定时回归 | `.github/workflows/ui-regression.yml` 必须显式配置 `QA_REPORT_VERSION`；版本切换时同步更新。 |
| GitHub 冒烟回归 | `.github/workflows/ui-smoke.yml` 如会产出测试报告，也必须与当前版本号一致。 |
| 本地回归 | 本地执行全量/专项回归前，确认环境变量 `QA_REPORT_VERSION` 与当前版本一致。 |
| 专项脚本 | SEO、Heading、内容对比等专项脚本默认读取 `QA_REPORT_VERSION`；若手工传 `--version`，必须传当前测试版本。 |
| GitHub Pages 报告 | 已部署的旧报告不会自动变更版本号，必须等下一次 UI Regression 跑完并部署后才会展示新版本。 |

## 检查命令

版本切换或修改 CI 后，至少执行一次：

```powershell
rg "V旧版本号|QA_REPORT_VERSION|DEFAULT_REPORT_VERSION" .github framework scripts README.md docs -S
```

如果仍发现旧版本号出现在当前报告配置、默认值或脚本参数中，需要先修正再执行/发布回归报告。
