# 历史继承规则

本文件记录已经被产品或测试口径确认、并且会跨版本继续生效的规则。新版本需求文档不是孤立来源；除非新版本明确说明并经产品/用户确认覆盖旧规则，否则本文件中的规则默认继续有效。

“后续版本”按代码分支继承关系判断，不只按版本号大小判断。两个版本若从同一主分支并行拉取，后创建的规则不能自动应用到另一条并行分支；只有相关需求或实现已合入其共同基线，或产品明确要求同步时，才作为该版本的验收规则。

## 使用规则

每个新版本开测前必须先读取本文件，并把适用规则写入需求追溯矩阵。

写入矩阵前必须核对目标版本的分支起点、合并记录和需求关系。来源版本与目标版本为并行分支时，规则标记为“不适用/未继承”，不得据此提交目标版本缺陷。

若最新需求文档、截图、表格或代码实现与历史继承规则冲突：

1. 先记录为 `文档冲突 / 需求遗漏` 或 `待确认`。
2. 不静默忽略冲突。
3. 不因为页面遵循历史规则而直接报产品缺陷。
4. 只有产品/用户明确确认“本版本覆盖旧规则”时，才更新本文件并按新规则验收。

发现新的跨版本规则后：

1. 在当前版本问题清单中说明来源和用户/产品确认口径。
2. 在本文件新增一行规则，给出规则 ID、来源版本和适用范围。
3. 若可自动化，补到固定回归或专项脚本索引；若不可自动化，写明人工检查方式。
4. 下个版本开测时，把规则写入需求追溯矩阵并检查新 PRD 是否冲突。

## 版本收尾检查

每个版本测试收尾时，必须回看以下材料，判断是否有需要沉淀为跨版本继承规则的内容：

- 当前版本问题清单
- 未测 / 阻塞项
- 待确认 / 部分覆盖项
- 文档冲突 / 需求遗漏项
- 用户或产品在对话中明确确认的验收口径
- 因需求变更关闭、忽略或降级的问题

满足以下任一条件时，应补充到本文件：

1. 该规则后续版本仍默认适用。
2. 该规则用于避免把历史需求误带入新版本。
3. 该规则用于避免把新文档遗漏误报为页面缺陷。
4. 该规则影响固定回归、问题分类或发布判断。

若确认没有需要继承的规则，也要在版本总结或问题清单中写明“本轮无新增历史继承规则”。
