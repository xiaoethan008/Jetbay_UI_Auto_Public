# 文案校验规则

## 核心规则

多语言和页面文案回归时，不能只检查翻译 key、英文残留、品牌词残留和主标题，还必须逐模块检查核心业务术语是否一致。

同一页面、同一业务模块内，核心术语应与需求文档、翻译表或产品确认口径保持一致；如果没有明确口径，应把术语混用记录为文案一致性问题或待确认项。

## 必查范围

| 范围 | 检查要求 |
| --- | --- |
| Hero / H1 / H2 | 标题和副标题使用的核心业务词与需求一致。 |
| FAQ / 折叠面板 | 每个问题标题和展开内容都要检查，不能只验证 FAQ 模块存在。 |
| 卡片 / 列表 / 筛选项 | 卡片标题、字段名、状态、CTA、空状态文案术语统一。 |
| 表单 / 弹窗 / Toast | Label、placeholder、错误提示、成功提示、提交后页面文案术语统一。 |
| Footer / 底部营销模块 | 底部 CTA、轮播、推荐模块也纳入可见文案检查。 |
| SEO Meta / Alt | 只有需求明确纳入时才作为缺陷；否则单独列为范围确认项。 |

## 执行方法

1. 从需求文档、翻译表、页面标题和产品确认信息中整理“本版本术语表”。
2. 对新增或改动页面按模块逐项读取可见文案，包含默认折叠项、hover、弹窗和移动端菜单。
3. 对同一术语的不同写法做一次全文搜索和截图确认。
4. 发现混用时，先判断是否有明确需求口径；有口径则记缺陷，无口径则记待确认。
5. 问题清单中必须写明“期望术语”“实际术语”“出现位置”和截图/URL。

## 示例

Empty Leg 中文页面如果产品口径为 `空腿航班`，则 FAQ 中不应混用 `空驶航班`：

- 期望：`预订空腿航班前需要考虑哪些因素？`
- 实际：`预订空驶航班前需要考虑哪些因素？`
- 判断：同一页面核心业务术语不一致，按文案一致性问题记录；若产品确认改用其他统一词，例如 `空机优惠`，则以产品确认词为准。

## 优先级建议

| 场景 | 优先级 |
| --- | --- |
| 主流程、首屏、核心转化 CTA、表单错误提示术语错误 | P1 |
| FAQ、底部模块、说明文案中术语混用但不阻断流程 | P2 |
| SEO Alt、不可见 DOM、历史隐藏素材中的术语差异 | 待确认，除非需求明确纳入 |
