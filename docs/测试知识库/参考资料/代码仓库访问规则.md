# 代码仓库访问规则

本文档记录 JETBAY UI 自动化项目在读取业务代码仓库时的边界，避免测试、定位和沉淀规则时误操作业务代码远端。

## 适用仓库

| 仓库 | 本地路径 | 远端仓库 | 用途 |
| --- | --- | --- | --- |
| 前端业务代码 | `D:\UITest\Jetbay_Code\jetbay-fe-web` | `git@codeup.aliyun.com:61cd193f6112fe9819da8c9b/jetbay/jetbay-fe-web.git` | 只读查看页面、组件、接口调用、SEO 与表单逻辑 |
| 后端业务代码 | `D:\UITest\Jetbay_Code\jetbay-java-web` | `git@codeup.aliyun.com:61cd193f6112fe9819da8c9b/jetbay/jetbay-java-web.git` | 只读查看接口、Controller、Service、Mapper、配置和测试数据逻辑 |

## 允许操作

- 可以读取本地文件、搜索代码、查看分支、查看提交历史、查看 diff 和 remote 信息。
- 可以基于代码做缺陷定位、根因分析、风险判断、补充测试用例和补充测试 Checklist。
- 如需从远端同步最新代码，仅做只读类操作，例如 `git fetch`、`git pull`、`git ls-remote`；执行前先确认不会产生本地冲突。
- 每个版本测试前，需要同步 dev 分支并分析改动点；同步前必须先检查 `git status --short`，同步时优先使用 `git pull --ff-only`。

## 禁止操作

- 禁止向 `jetbay-fe-web` 和 `jetbay-java-web` 的远端执行 `git push`。
- 禁止创建、合并、关闭远端 PR/MR，或对远端分支、tag 做删除、覆盖、改写历史等操作。
- 未经用户明确要求，不在这两个业务代码仓库内提交 commit。
- 不把测试脚本、问题清单、截图、临时文件提交到这两个业务代码仓库。

## 工作原则

- `Jetbay_UI_Auto_Public` 是 QA 自动化与测试资产仓库，可以按任务维护测试代码、文档、规则和报告。
- `jetbay-fe-web` 与 `jetbay-java-web` 只作为业务代码阅读来源，用来辅助理解页面实现、接口来源和潜在缺陷。
- 发现业务代码问题时，输出问题清单、复现步骤、影响范围和定位线索；不直接向业务代码远端提交修复。
- 代码改动分析结果归档到当前版本 `artifacts/官网Vx.x.x（模块名）/代码改动分析/代码改动分析.md`。
