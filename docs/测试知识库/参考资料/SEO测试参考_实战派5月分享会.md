# SEO 测试参考：实战派 5 月分享会与 Jet-Bay 案例

来源文档：`SEO_实战派5月分享会_公司实战案例.docx`

本文用于后续 Jet-Bay 官网 SEO 测试、回归测试和问题清单评审时统一检查口径。

## 核心原则

SEO 不是一次性配置项，而是持续循环：

1. 被抓取：搜索引擎能发现 URL，并能访问页面。
2. 被理解：HTML 结构、内容主题、链接关系和实体关系清晰。
3. 被匹配：页面内容与用户搜索意图、关键词和主题相关。
4. 被验证：页面体验、性能、状态码、索引质量和外部信号稳定。

做测试时先验证“爬虫能否真实看见和理解页面”，再验证 Schema、GEO、FAQ、文案优化等增强项。

## SEO 测试检查清单

| 分类 | 检查项 | 测试要点 |
| --- | --- | --- |
| 抓取入口 | `robots.txt` | 不应误拦截核心页面；低价值路径可按策略限制。 |
| 抓取入口 | `sitemap.xml` | sitemap 中 URL 应可访问；重要页面应纳入 sitemap；404/跳转链 URL 应清理。 |
| 页面状态 | HTTP 状态码 | 正常页面返回 200；不存在资源返回 404/410；避免 Soft 404。 |
| 页面状态 | 跳转治理 | 减少 3xx 跳链；废弃 URL 应按需求配置 301 到正确目标。 |
| HTML 语义 | TDK | `<title>`、`meta description` 与页面主题一致；重点落地页需按需求校验。 |
| HTML 语义 | Heading 层级 | 通常建议页面有一个主 H1；H2/H3 按内容层级展开，避免乱序和重复堆砌。 |
| HTML 语义 | 语义标签 | 优先使用 `header/main/section/article/nav/footer` 等结构表达页面语义。 |
| 链接可发现 | 真实链接 | 重要跳转尽量使用真实 `<a href>`，避免只依赖 `onclick` 或纯 JS 跳转。 |
| 渲染可见性 | SSR/SSG/ISR | 核心正文、标题和链接应在首屏 HTML 或可被爬虫稳定渲染后读取。 |
| 渲染可见性 | JS-only 内容 | 避免正文完全依赖客户端 JS 后置渲染，尤其是详情页主体内容。 |
| 索引策略 | `index/follow` | 核心落地页保持可索引；低价值筛选页、重复页按策略 `noindex`。 |
| 归一化 | Canonical | 参数页、排序页、分页页、重复内容页应指向主版本；dev 未配置时需在报告中说明环境限制。 |
| 国际化 | Hreflang/Locale | 多地区 URL 的 canonical、hreflang、index 策略应一致；避免重复英文内容消耗抓取预算。 |
| 多端一致性 | Web/H5/小程序 | 同主题多端内容不要出现语义冲突；核心内容优先集中到主域名积累权重。 |
| 结构化数据 | FAQ Schema 等 | 在页面可抓取和语义基础稳定后，再校验 FAQ Schema、Rich Results 等增强项。 |
| 内容策略 | 答案优先内容 | 标题、首段和 FAQ 应明确回答用户搜索意图，提升被召回和被引用概率。 |
| 内容策略 | 实体显著性 | 品牌、地点、机型、航线、服务等实体应清晰出现，并与页面主题一致。 |
| GEO/AI 搜索 | 向量友好标题 | 标题和小标题应具体、可理解，避免过度营销话术和含糊表达。 |
| 性能体验 | Core Web Vitals | 重点关注 LCP、CLS、INP；上线前和回归时记录异常页面。 |
| 性能体验 | CLS | 首屏布局需稳定；异步数据、侧边栏、图片容器、广告位等应预留尺寸。 |
| 性能体验 | LCP | 首屏主图、字体、核心 CSS、接口等待、无效资源都会影响 LCP。 |
| 资源治理 | 图片 | 优先 WebP/AVIF；按需尺寸、压缩、懒加载；避免移动端加载仅 PC hover 使用的图片。 |
| 资源治理 | 字体 | 优先使用更适合 Web 的字体格式，如 `.woff2`；避免移动端加载过大的字体包。 |
| 缓存策略 | CDN/接口缓存 | 静态资源和高频接口设置合理缓存与失效策略，降低 TTFB 并提升稳定性。 |
| 关键资源 | Preload | 对首屏关键字体、主图、核心 CSS 按需预加载。 |
| 工具辅助 | AITDK | 快速检查 TDK、Heading 层级和基础 SEO 要素。 |
| 工具辅助 | Google Rich Results Test | 检查爬虫渲染结果和结构化数据建议。 |
| 工具辅助 | Google Search Console | 观察收录、抓取、覆盖率、关键词和 Core Web Vitals。 |
| 工具辅助 | PageSpeed/Lighthouse | 分析 LCP/CLS/INP、资源体积、阻塞请求和性能瓶颈。 |

## Jet-Bay 典型案例回归点

| 案例 | 历史问题 | 后续测试口径 |
| --- | --- | --- |
| CLS 治理 | 初始加载时左侧菜单收缩，数据请求后插入页面导致布局抖动。 | 检查首屏布局是否稳定；菜单、列表、异步数据区域是否在服务端或初始布局中预留空间。 |
| Soft 404 | 不存在页面前端 301 到 `/404`，但 document 请求最终返回 200。 | 不存在资源必须由服务端返回 404/410；404 页面可以友好展示，但状态码必须正确。 |
| 多 locale 重复内容 | 多地区文章内容均为英文，产生大量“已抓取但未编入索引”。 | 校验 locale 归一化、canonical、index/noindex、hreflang 策略；确认重复内容不会消耗抓取预算。 |
| LCP 治理 | 移动端首页 LCP 高，原因包括字体包过大、图片未压缩、移动端加载 PC hover 图片。 | Lighthouse/Network 检查字体、图片、无效移动资源、首屏主内容加载时间和资源体积。 |

## 问题清单输出建议

SEO 问题清单不要只输出机器字段，建议包含：

| 字段 | 说明 |
| --- | --- |
| 问题 ID | 如 `SEO-001`，便于复测追踪。 |
| 优先级 | P0/P1/P2，按影响收录、抓取、核心页面程度判断。 |
| 模块/页面类型 | 如 News、Blogs、Destination、Private Jet Charter。 |
| 问题类型 | sitemap、robots、TDK、Heading、canonical、hreflang、status、Soft 404、LCP、CLS 等。 |
| 期望结果 | 需求文档或 SEO 规范中的正确表现。 |
| 实际结果 | 当前页面、HTTP 响应或渲染后的实际表现。 |
| 影响范围 | 影响 URL 数、影响模块、是否为核心落地页。 |
| 示例 URL | 每条问题保留 1 到 3 个代表页面，长列表拆到明细文件。 |
| 证据 | 截图、响应头、computed CSS、Lighthouse 数据、GSC 口径说明等。 |
| 是否已修复 | 保留历史问题，不删除；用字段标记修复状态。 |

## 后续自动化优先级

1. sitemap URL 可访问性与状态码扫描。
2. Soft 404 检查：页面文案、状态码和 document 请求结果一致性。
3. TDK、Heading、语义结构检查。
4. 真实 `<a href>` 链接可发现性检查。
5. canonical、hreflang、index/follow 检查，并支持环境例外配置。
6. 图片 alt、图片体积、字体体积和移动端无效资源检查。
7. Lighthouse/Performance 抽样检查 LCP、CLS、INP。
8. 内容详情页正文富文本样式与 SEO 规范检查。

## 测试时的判断顺序

1. 先看 URL 是否存在、状态码是否正确。
2. 再看 robots/sitemap 是否允许并推荐抓取。
3. 再看页面 HTML 是否能表达主题和核心内容。
4. 再看 canonical/hreflang/index 策略是否避免重复和冲突。
5. 再看性能、资源、CLS/LCP 是否会拖累页面体验。
6. 最后再看 FAQ Schema、GEO 文案、实体显著性等增强项。
