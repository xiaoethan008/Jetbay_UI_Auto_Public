# 历史 Bug 模式库

本文件用于沉淀 JETBAY 官网测试中已经踩过的坑。以后发现新 bug 或复盘漏测时，优先补充到这里，再决定是否补测试用例、自动化脚本或 skill。

## 使用规则

- 每次发现漏测，先回答：为什么之前漏了、影响哪些模块、以后如何避免。
- 能自动化的场景，补到 `tests/` 或 `scripts/`。
- 不能稳定自动化的场景，补到 checklist，并在回归时人工/探索性验证。
- 已删除或需求变更的内容，必须在问题清单中标记，不继续当作缺陷上报。

## 历史模式

### 表单提交未校验登录态

- 现象：用户登录后打开表单，删除本地 token/cookie/sessionStorage 后仍可提交成功，甚至进入 thankyou 页面。
- 漏测原因：之前只验证了未填写字段、正常提交、按钮可点击，没有覆盖“登录态过期后提交”的状态组合。
- 避免规则：所有需要登录或带用户身份的提交表单，都要覆盖 token 失效场景。
- 检查方法：
  1. 登录账号。
  2. 打开目标提交弹窗或表单。
  3. 删除 `jet-bay-token`、`JETBAY_INFO`、`tt_sessionId` 等本地认证字段。
  4. 点击提交。
  5. 校验页面提示重新登录/登录过期，并刷新为未登录态，不得进入成功页。
- 已沉淀：
  - 用例：`TC-057`
  - 自动化：`tests/test_login_expired_form_submit.py`

### 表单提交后按钮或底部区域被遮挡

- 现象：点击提交后出现错误提示，但底部提交按钮被弹窗容器裁切或遮挡，用户无法继续操作。
- 漏测原因：只校验了错误提示是否出现，没有校验错误态下按钮是否仍可见、可操作。
- 避免规则：表单负向提交后必须检查按钮、协议勾选区、错误提示三者是否同时可见且不互相遮挡。
- 检查方法：提交一次空表单或错误数据后截图，计算提交按钮可见比例，必要时检查滚动区域。

### 多段航程表单高度超出 Hero 区域

- 现象：Private Jet Charter 的 Multi-City 增加第三段航程后，`Search Available Aircraft` 按钮被 Hero 容器裁切。
- 漏测原因：之前验证 DOM 中按钮存在，没有验证用户实际可见区域。
- 避免规则：对动态增高的表单，必须检查关键 CTA 的实际可见比例，而不是只检查元素存在。
- 已沉淀：
  - 用例：`TC-044`
  - 自动化：`tests/test_private_jet_entry.py`

### 地区切换后数据未刷新或数据源不一致

- 现象：切换国家/地区后，航线、机型或推荐数据仍展示旧地区数据，或页面字段与 Excel/DB/API 不一致。
- 漏测原因：只检查默认地区，没有逐个切换地区并对比原始数据源。
- 避免规则：凡是依赖地区/语言/币种的模块，都要按地区逐一切换，并对比 Excel、DB 或接口返回。
- 已沉淀：
  - 用例：`TC-056`、`TC-060`、`TC-061`
  - 脚本：`scripts/compare_world_cup_routes_excel.py`、`scripts/validate_popular_aircraft_by_locale.py`、`scripts/compare_popular_aircraft_with_db.py`

### 图片地址误判

- 现象：页面使用 Next.js 图片代理地址，如 `/_next/image?url=...`，直接与数据库原始图片地址比较会误判。
- 漏测原因：未解析代理 URL 中的 `url` 参数，导致把同一张图片判断成不同图片。
- 避免规则：图片 URL 对比前必须解码真实资源地址；同时区分相似但不同机型，例如 `Gulfstream G650` 和 `Gulfstream G650ER`。
- 已沉淀：`ui-visual-qa-guard` skill、Popular Private Jet DB 对比脚本。

### 删除线需求误报

- 现象：需求文档中带删除线的文字被当成仍需实现的需求，导致误报。
- 漏测原因：文档提取后没有保留或识别删除线语义。
- 避免规则：带删除线的内容视为已删除需求，测试时不得作为预期；若不确定，先在测试记录中标记“待确认”。

### 装饰性标点或伪元素误判

- 现象：标题后的装饰点、伪元素、背景图文字等被当成正文缺失或多余。
- 漏测原因：只读 DOM 文本，未结合截图和视觉上下文。
- 避免规则：UI 文案类缺陷要结合可见截图、computed style、伪元素和设计意图判断。
- 已沉淀：`ui-visual-qa-guard` skill。

### 轮播只测第一帧

- 现象：首页 Banner 或活动 Banner 是轮播组件，只检查第一帧会漏掉后续帧内容、链接或图片问题。
- 漏测原因：静态截图后没有切换轮播点或等待自动轮播。
- 避免规则：轮播组件至少检查首帧、手动切换帧、链接目标和移动端展示。

### 弹窗下拉层定位错误

- 现象：国家筛选、阶段筛选、地区切换等下拉层存在，但脚本点错元素或截图位置不完整，导致误报“不存在”。
- 漏测原因：选择器过于依赖英文文案或单一层级，没有结合可见区域截图。
- 避免规则：下拉组件测试要同时检查按钮展开态、浮层可见性、选项数量、选择后状态变化和清空操作。

### CDN 或缓存导致间歇性 SEO 结果

- 现象：同一路径 SEO title/description/keywords 一会儿新一会儿旧。
- 漏测原因：只请求一次，未记录 cache header、etag、instance。
- 避免规则：SEO 变更验证至少连续请求多次，并记录 `x-nextjs-cache`、`etag`、实例 ID 等头信息。

### dev 环境能力未配置导致误报

- 现象：dev 环境未配置 canonical，却按生产规则报 canonical 缺失。
- 漏测原因：未区分环境配置差异。
- 避免规则：SEO 扫描要支持环境开关。dev 未启用的能力不作为缺陷，只在备注中说明。
