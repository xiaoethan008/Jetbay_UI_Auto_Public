# BUG-DEV-20260814-005：Private Jet Charter 多程 4 段时表单覆盖下一内容区

- 分类：产品缺陷 / 视觉布局
- 优先级：P1
- 状态：未修复
- 版本：V4.1.4
- 环境：dev，`https://dev.jet-bay.com/zh-cn/private-jet-charter`
- 分支 / Commit：`main` / `7106418f38954ae4cf20ba2a776b3b3e8b1b72da`
- 浏览器 / 视口：Chrome 桌面端，截图约 `1900 × 982`
- Locale：`zh-cn`
- 关联用例：`TC-044`、`tests/test_private_jet_entry.py::test_private_jet_multi_city_three_legs_keeps_search_cta_visible`
- 发现方式：用户截图视觉确认；不是 DOM 文本推断

## 前置条件

1. dev 官网可正常访问。
2. 打开简体中文 Private Jet Charter 页面。

## 复现步骤

1. 访问 `https://dev.jet-bay.com/zh-cn/private-jet-charter`。
2. 在首屏搜索表单中切换到“多程”。
3. 连续点击“添加航段”，将行程增加到 4 段。
4. 观察多程表单底部、Hero 区域和下一内容区的布局。

## 预期结果

页面容器应随 4 段表单高度正常向下扩展或重排；“添加航段”“搜索可用公务机”按钮完整可见，表单与下一内容区之间没有遮挡、透叠或文字重叠。

## 实际结果

多程表单向下超出 Hero 区域，下一内容区仍停留在原位置，导致搜索按钮下方的介绍文字、指标和背景图片与表单发生明显覆盖和层叠。

## 影响与稳定性

- 影响用户读取页面内容，并降低搜索入口的视觉可信度。
- 影响多程 4 段及可能更多航段的桌面端场景。
- 当前证据为用户稳定复现截图；待开发修复后补充多视口、多语言复测。

## 诊断线索

以下仅为线索，尚未通过源码确认：Hero 或搜索表单外层可能使用固定高度、绝对定位或 `overflow` 约束，新增航段后父容器高度没有参与后续文档流计算。

## 漏测原因与补测建议

现有 `TC-044` 只验证多程增加到 3 段时搜索按钮可见，没有覆盖 4 段的最大/边界布局。修复后应扩展为 3 段、4 段及产品允许的最大航段数，并覆盖 `global`、`en-us`、`zh-cn` 以及至少两个桌面视口。
