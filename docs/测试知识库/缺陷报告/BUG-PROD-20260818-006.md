# BUG-PROD-20260818-006：Destination 城市列表请求触发生产空指针异常

- 关联接口：`GET /web/destination/city/list`
- 关联方法：`DestinationController.pageCityList`

## 前置条件

生产环境存在缺失 `similar` 参数、无效/已下线 Destination slug，或异常 Destination 数据的城市列表请求。

## 最小复现方向

1. 请求 `/web/destination/city/list`。
2. 不传 `similar`，或传入数据库中不存在/已删除的 `id`。
3. 使用 `flag=country&similar=0` 或 `similar=1` 进入 Destination 查询分支。
4. 检查接口响应和 `jetbay-java-web.log`。

复现必须先在非生产环境执行；生产环境仅查询现有日志，不主动构造异常请求。

## 预期结果

接口应返回明确的参数校验错误、记录不存在或空分页结果；单个异常请求不应产生未捕获异常，也不应触发严重生产告警。

## 实际结果

`pageCityList` 抛出非 `ServiceException` 异常。日志切面仅记录 `ex.getMessage()`，最终告警显示：

```text
请求异常 → ID: d4e018cf-2a01-4539-84ac-e28c1a72dda5 |
方法名称: com.jetbay.web.controller.web.DestinationController.pageCityList |
异常: null
```

## 源码证据

生产 Commit `ed1aae4f` 中：

1. `DestinationCityPageReq.similar` 是可空 `Integer`，但 Service 使用 `req.getSimilar() == 0/1` 自动拆箱，缺少 null 校验。
2. `getBySlug(req.getId())` 可能返回 null，但代码随后直接调用 `destination.getId()` 和 `destination.getSimilarCities()`。
3. 响应映射使用 `item.getDestinationType() == 2`，若历史数据字段为空也会自动拆箱失败。
4. `LoggerAspect.java:116` 只记录 `ex.getMessage()`，没有记录异常对象和完整堆栈，因此 NPE 显示为 `异常: null`。

上述为已核对的代码风险；要从多个空指针入口中确定本次实际入口，仍需取得同请求 ID 的“请求开始”日志参数或完整堆栈。

## 影响

- Destination 国家/城市页面的城市列表或相似城市模块可能加载失败。
- 9 分钟内累计 103 次，生产错误量达到严重告警级别。
- 无完整堆栈导致定位时间延长，影响生产可观测性。

## 修复建议

1. 对 `req`、`id`、`similar` 和 `getBySlug` 返回值做显式校验。
2. 使用 `Objects.equals(req.getSimilar(), 0/1)` 避免自动拆箱 NPE。
3. 使用 `Objects.equals(item.getDestinationType(), 2)` 兼容异常历史数据。
4. 参数无效或记录不存在时返回统一业务错误/空分页结果。
5. 日志改为传入完整异常对象，保留堆栈。
