# Agent探索执行与证据规范

适用：需求探索、版本专项、失败诊断。用户于2026-09-21同意采用精简输出、阶段检查点、即时证据关联，并试验CLI。现有pytest + Playwright固定回归继续使用；本规范不改变业务验收口径。

## 本次实施范围与验收

1. 新增 `framework/exploration_journal.py`：原子保存checkpoint、用例尝试记录、证据路径与SHA256、待清理事项；运行输出仅返回摘要。无业务系统依赖。
2. 新增离线基础设施测试：验证进程重开后状态读取、写入失败恢复、证据缺失/变化拒绝、敏感字段脱敏、越界路径拒绝。执行 `python -m unittest discover -s tests -p test_exploration_journal.py -v`。
3. 一次性CLI对比保存在 `artifacts/exploration-cli-pilot/`，使用CMS登录页只读交互，记录版本、耗时、输出字节及截图/快照/Trace。未登录、未提交业务表单，不纳入固定业务回归。
4. 回退：停止使用该独立记录工具即可；既有fixture、定位器、CI命令均不依赖它。无业务代码改动，无部署审批步骤。

实施验证：6项离线测试通过unittest及pytest入口；CMS登录页只读试验两种方式均完成，CLI快照/截图/Trace已归档。单轮API为3.650秒、CLI为6.912秒，不能据此声称CLI更快；未测量Token账单。详细记录位于 `artifacts/exploration-cli-pilot/README.md`。CLI试验发现所装版本输出未压缩Trace，已保留原文件并打包ZIP，不能只搜索ZIP就判没有Trace。

## 选择执行方式

| 工作 | 方式 |
| --- | --- |
| 未知页面探索 | CLI或MCP；先查看所装版本帮助，按需读取局部快照 |
| 明确的UI/API步骤 | 直接调用Playwright/API，返回断言结果 |
| 固定回归 | pytest + Playwright + Allure；CI不逐步调用大模型 |
| 失败分析 | 摘要 → 对应用例证据 → 必要时读取Trace/网络明细 |

不要把快照ref（例如e12）作为长期定位器。固定脚本优先使用稳定的role/label/testid。录制步骤必须补断言、数据隔离和清理，才是回归用例。

## 输出约定

- 每步默认输出：用例ID、状态、简短实际结果、证据路径、下一步。完整JSON/DOM/控制台日志先落盘，按字段/片段读取；不能整页反复打印。
- API证据优先保存白名单字段，如业务code、目标字段、对象ID；不保存登录请求、Cookie、Token、完整storage state。
- 记录器仅按敏感字段名和Bearer模式脱敏，**不保证清除任意正文内的秘密或个人信息**。截图、Trace及外部文件未自动脱敏，采集者须控制内容；存受限制品目录，不提交Git。
- 快照用于理解结构，截图用于可见结果，Trace用于操作和网络定位。页面文本存在不能代替可见性断言。

## 检查点与恢复

每个环境/模块/执行者使用独立目录。目录固定绑定环境；禁止重用同一个checkpoint给另一个环境。每条业务操作前调用begin；采集证据后立即attach/finish，不等全轮结束再整理。

```python
from framework.exploration_journal import ExplorationJournal

run = ExplorationJournal.create(
    "artifacts/my-version/exploration/cms-run-01",
    environment="test", module="CMS Page",
)
step = run.begin("TC-001", expected="页面名称可见", next_action="读取字段并截图")
# 用真实执行结果替换下面示例数据；不要凭示例直接判通过。
run.json_evidence(step, {"field": "pageName", "visible": True})
# page.screenshot(path=str(run.root / "page-name.png"))
# run.attach(step, "page-name.png")
run.finish(step, status="passed", actual="字段可见；已记录检查结果")
print(run.summary())
```

已有目录使用 `ExplorationJournal(directory)` 打开，不再次create：

```powershell
python -m framework.exploration_journal artifacts/my-version/exploration/cms-run-01 --limit 5
```

- `running`表示中断或尚未结束，不能当作未执行后直接重放。先读取系统当前状态，确认上一操作是否已经生效，避免重复发布/提交。
- 一个用例复测使用新attempt，保留第一次失败。`partial`/`blocked`不能计为通过。
- 写操作前保存基线，用 `require_cleanup(key, action=..., baseline=...)`登记恢复事项；回读系统状态并保存核对证据后才调用 `confirm_cleanup`。
- 工具记录人工核对结果，不自动撤销业务动作，也不自动保证断言正确。passed/failed至少须附一份未发生变化的执行证据。
- `.journal.lock`避免并发覆盖。进程被强杀可能留锁；确认对应进程已退出并核对checkpoint后才移除该锁文件。不要自动删除他人的锁；并行工作使用独立目录。

## CLI试验及采用条件

先固定CLI版本并查看 `--help`，使用命名会话。按实际版本支持的命令开启Trace，保存快照与截图，最后关闭本次会话。持久化登录不是默认要求，不将凭据放进命令参数。

同一目标、同一动作与断言，对比原方式和CLI：

- 总耗时（安装耗时单独记）、执行是否成功；
- 原始工具输出字节、实际提供模型的摘要字节；
- 截图、结构快照、Trace是否存在且能打开；
- 清理和恢复是否可验证。

输出字节不是Token账单。没有同模型实测Token、同场景重复样本时，不声称“省4倍”或性能优劣已确定。短流程结果不能外推长流程稳定性。

参考：[CLI官方文档](https://github.com/microsoft/playwright-cli)、[MCP官方配置](https://github.com/microsoft/playwright-mcp)。文档及命令可能变化，按安装版本核实。
