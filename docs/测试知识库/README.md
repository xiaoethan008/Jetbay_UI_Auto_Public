# JETBAY 官网测试知识库

本目录用于沉淀跨版本可复用的测试经验。它不是执行报告，也不是聊天记录；它记录“以后每次回归都应该先知道的规则、风险和历史复测点”。

## 使用顺序

每次开始新版本测试前，先按顺序读取：

1. `环境与误报规则.md`
2. `测试策略与质量门禁.md`
3. `需求追溯矩阵规范.md`
4. `官网回归基线.md`
5. `历史问题与复测点.md`
6. `版本测试记录索引.md`
7. 从业务代码仓库 dev 分支同步最新代码，只读分析本版本改动点
8. 当前版本 `artifacts/官网Vx.x.x（模块名）/` 目录

## 更新原则

- 每个版本开测前，先从业务代码仓库 dev 分支同步最新代码并分析改动点，分析结果归档到当前版本目录。
- 每个版本必须维护一份 `需求追溯矩阵_Vx.x.x.csv`，P0/P1 不允许长期处于“待补”。
- 每次发现跨版本会复现的风险，补到 `历史问题与复测点.md`。
- 每次确认环境差异或误报规则，补到 `环境与误报规则.md`。
- 每次新增固定回归能力，补到 `官网回归基线.md`。
- 每次完成新版本测试，补到 `版本测试记录索引.md`。
- 只记录长期有用的信息；具体截图、明细和临时输出放在 `artifacts`。

## 目录说明

- 根目录下文件是知识库主入口，用于快速接续上下文。
- `参考资料/` 放详细材料，只有需要复盘、补规则或查专项细节时再打开。
