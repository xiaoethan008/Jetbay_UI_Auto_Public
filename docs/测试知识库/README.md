# JETBAY 官网测试知识库

本目录用于沉淀跨版本可复用的测试经验。它不是执行报告，也不是聊天记录；它记录“以后每次回归都应该先知道的规则、风险和历史复测点”。

## 使用顺序

每次开始新版本测试前，先按顺序读取：

1. `环境与误报规则.md`
2. `历史继承规则.md`
3. `测试策略与质量门禁.md`
4. `需求追溯矩阵规范.md`
5. `自动化用例追溯矩阵.md`
6. `专项脚本索引.md`
7. `官网回归基线.md`
8. `官网回归基线.md` 中对应模块及统一测试用例清单
9. `历史问题与复测点.md`
10. `版本测试记录索引.md`
11. 从业务代码仓库 dev 分支同步最新代码，只读分析本版本改动点
12. 当前版本 `artifacts/官网Vx.x.x（模块名）/` 目录

## 更新原则

- 每个版本开测前，先从业务代码仓库 dev 分支同步最新代码并分析改动点，分析结果归档到当前版本目录。
- 每个版本拆需求前，先读取 `历史继承规则.md`；新需求若与历史已确认规则冲突，记录为“文档冲突/需求遗漏”或“待确认”，不得静默忽略。
- 每个版本必须维护一份 `需求追溯矩阵_Vx.x.x.csv`，P0/P1 不允许长期处于“待补”。
- 每次发现跨版本会复现的风险，补到 `历史问题与复测点.md`。
- 每次确认环境差异或误报规则，补到 `环境与误报规则.md`。
- 每次新增测试脚本前，先确认它是固定回归脚本还是一次性专项脚本；一次性脚本不写入固定回归清单。
- 每次新增固定回归能力，补到 `官网回归基线.md`。
- 版本或模块用例整合进统一测试用例清单和 `官网回归基线.md` 后，不再在知识库根目录保留独立的版本回归用例文件，避免形成多个事实来源。
- 每次完成新版本测试，补到 `版本测试记录索引.md`。
- 新建版本目录时，必须在同一次改动中同步更新本表和 `版本测试记录索引.md`，不得只创建 `artifacts` 目录而遗漏知识库入口。
- 每次版本收尾时，必须回看问题清单、待确认项、未测/阻塞项和用户确认口径；需要后续版本继承的规则补到 `历史继承规则.md`，没有新增也要在版本总结中说明。
- 只记录长期有用的信息；具体截图、明细和临时输出放在 `artifacts`。

## 目录说明

- 根目录下文件是知识库主入口，用于快速接续上下文。
- `参考资料/` 放详细材料，只有需要复盘、补规则或查专项细节时再打开。
